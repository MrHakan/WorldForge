# v5.4.0 — WebGL Atlas

Close zoom in v5.3 could synchronously rasterize many 512-pixel-per-cell terrain tiles, blocking input while still magnifying a soft overview. v5.4 renders terrain and settlement faces through WebGL instead.

- A persistent, half-cell terrain mesh is uploaded once per world. Camera movement changes uniforms, without rasterizing tiles or uploading world textures again.
- Packed elevation and climate fields drive per-pixel coastal water, biome colors, rock, snow, directional shading and procedural surface detail.
- All 27 settlement building types use cached GPU triangles from the same procedural model definitions as the Canvas fallback. Roof seams, masonry courses, recessed windows, lintels and awnings remain geometry at close zoom.
- Zoom extends to 40×. Mouse and touch input coalesce into animation frames; two-finger gestures support panning as well as scaling.
- Device-pixel rendering supports up to 3× DPR within an 8-megapixel framebuffer budget. WebGL 1 and 16-bit indexed mesh bands avoid requiring WebGL 2, float textures or optional vertex-texture support on mobile Safari.
- Context loss temporarily activates Canvas rendering, then recreates GPU resources on restoration. The Canvas path limits tile resolution, memory and work per frame.
- Technology, population gates, historical views, world fingerprints and save formats retain their existing contracts.

## Validation

The browser regressions check compiled WebGL shaders, nonblank GPU pixels, stable terrain and building buffers during zoom, zero repeated terrain uploads, frame-coalesced wheel input, analytical layers, world wrapping, context loss/restoration, mobile DPR and unavailable-WebGL fallback. Existing browser checks still cover settlement selection, projections, navigation, save/import, simulation and five architectural stages.

Browser performance artifacts report CPU submission timings, not device-specific FPS claims. Physical iPad/Safari performance still depends on its GPU, viewport and browser resource limits.
