# v5.5.0 — Live Simulation

Advancing many years previously ran the full simulation on the page thread. Cooperative yielding helped between years, but an expensive year still blocked input, and most page data refreshed only after the entire job finished.

The new project-owned runtime uses native Web Workers and incremental state deltas. It runs the existing feature engines in an isolated worker, sends changed fields with acknowledgement-based backpressure, and commits coherent annual states to the existing world object. Terrain buffers, camera position and unchanged historical snapshots remain reusable. Active panels refresh during a job instead of waiting for completion.

Additional changes:

- Autoplay keeps one paced worker job alive across five-year steps instead of copying the entire world and restarting its engines for every tick.
- Living-character queries retain an index of active people and newly appended records instead of repeatedly scanning every dead historical character.
- Recent replay retention follows the world's configured snapshot interval. Forced intermediate snapshots no longer accumulate at annual density when the replay slider uses five-year intervals.
- Legacy warfare, urban, activity and logistics renderers skip hidden panels.
- Cancellation stops at a coherent state; superseded jobs cannot overwrite a newly forged or imported world. Worker startup failures retain the cooperative fallback.
- Immutable historical snapshot rows are tracked by identity between epoch rebases, reducing delta work and memory as history grows.

The save schema is unchanged. Past replay remains available at its configured interval. User-authored notes and static geographic layers are not sent again with each live update.

## Validation

Deterministic regression suites cover the simulation engines and delta operations, including append, trimming, deletion, epoch rebase, object-key safety, stable geometry and authored notes. The browser regression compares the worker with the actual full browser engine stack, checks responsiveness and intermediate data updates during long runs, and covers cancellation, world replacement and unavailable-worker fallback.

Web Workers documentation: https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers

Comlink was evaluated, but this runtime needs a specific state-delta and acknowledgement protocol rather than a general remote-object API: https://github.com/GoogleChromeLabs/comlink
