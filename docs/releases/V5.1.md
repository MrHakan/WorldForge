# v5.1.0 — Responsive Pages Workspace

WorldForge now uses the same complete runtime locally and on GitHub Pages. Long-running simulations have explicit ownership and cancellation, workspace navigation opens real panels, and releases follow a validated deployment.

## Simulation and concurrent work

- One active asynchronous simulation may mutate a world at a time. Overlapping async calls and synchronous mutations reject clearly; independent worlds can still run independently.
- Runtime ownership lives in a `WeakMap`. Loading a save made during a simulation clears its stale running flags without changing the original live job.
- Async execution yields before the first year and between batches. UI controls use one-year batches so cancellation takes effect at annual boundaries.
- Prioritized scheduler continuations also yield to normal browser tasks. Hidden tabs do not depend on `requestAnimationFrame` to finish a run.
- `AbortSignal`, explicit cancellation and error cleanup release ownership consistently.
- Manual steps, target years and automatic playback use the same async UI path. Playback waits for completion before scheduling another tick and has no obsolete 5,000-year UI ceiling.
- Generating, loading or importing a different world cancels the old job. A stale file read or completion cannot replace or repaint a newer world.

The simulation remains on the main thread, and the smallest complete annual step is synchronous. This release improves cooperative scheduling; it does not introduce a worker-thread simulation or change deterministic model rules.

## Pages and workspace

- The source HTML includes the full runtime; deployment no longer injects missing feature loaders.
- Classic entry scripts use `defer` while preserving their dependency order.
- Twenty-one compatibility bootstraps share normalized asset URLs, in-flight script promises, load/error events, timeouts and retry cleanup. Dependency checks share one fallback poll instead of one interval per loader.
- One browser release metadata module owns the application title and chrome. Historical component versions remain component versions.
- Panel classification uses exact IDs and CSS classes. Unmounted subpages are omitted, and nested activity, heritage and warfare views reveal their parent shell correctly.
- Workspace preferences tolerate unavailable storage and invalid modes.
- Hidden base panels and the adventure/story/encyclopedia sections defer their rendering until selected.
- Local save failures offer Export World; clipboard failures no longer report false success. Simulation cancellation is available from the Chronicle toolbar.

## Build, validation and publishing

Requires Node.js 22.16 or newer; CI uses Node.js 24. Browser runtime remains dependency-free. Playwright is a pinned development dependency.

```sh
npm ci
npm run dev
npm run test:syntax
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

The preview serves `http://127.0.0.1:4173/WorldForge/` so repository-relative paths are exercised locally. The clean `dist/` artifact contains only the entrypoint, runtime assets, license, `.nojekyll` and `release.json`.

The Pages workflow runs core, feature, rendering and warfare regressions concurrently, checks the real browser under `/WorldForge/`, deploys the resulting artifact, and then publishes `v5.1.0`. An existing release is preserved on subsequent pushes. Production deployments are serialized without cancelling an in-flight deployment; superseded validation jobs can be cancelled independently. Historical compatibility workflows remain available.

Regression coverage includes async ownership, save recovery, cross-world concurrency, deterministic chunking, cancellation, aborts, callback errors, loader deduplication/retry/deadlines, nested workspace visibility, unavailable preferences, production artifact contents, every displayed navigation destination, world replacement during a run, JSON import, local save failures and mobile overflow.

## Compatibility

Existing world save schemas and all earlier simulation systems are retained. No server or account is required to generate, simulate or author a world.
